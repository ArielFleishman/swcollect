# Running swcollect on a closed network

## 1. Build the bundle (outside, with internet and Docker)

```powershell
.\scripts\bundle_offline.ps1
```

It writes:
- `deploy/wheels/`: Linux wheels for the image (Python 3.12, manylinux)
- `wheels/`: Windows wheels, for a local `.venv` and the tests
- `deploy/images/*.tar`: `docker save` of TimescaleDB 2.17.2-pg16, Loki 3.3.2, Grafana OSS 11.4.0 and python:3.12.10-slim
- `deploy/MANIFEST.sha256`: the SHA256 of every file above

Carry the whole `swcollect` folder in.

## 2. Load and check (inside)

```powershell
.\scripts\load_offline.ps1          # or scripts/load_offline.sh on Linux
```

The script does six things:
1. verifies the manifest
2. runs `docker load`
3. builds `swcollect:0.1.0` from `deploy/wheels` only
4. starts PostgreSQL + TimescaleDB, Loki, the mock (rich), the collector and Grafana
5. runs the readiness check
6. confirms there is no route out (`scripts/smoke.ps1` does the same)

Then run the full end-to-end check against the mock (about 5 minutes):

```powershell
.\scripts\e2e.ps1                   # fresh volumes; 16 steps; then the "no route out" check
```

## 3. Point it at a real Orion

1. **Create a read-only Orion account,** with an account limitation to the network. Use the same account rules as swcheck (README → Service account).
2. **Add a profile per network** to `deploy/config.docker.yaml`:

   ```yaml
   networks:
     - name: isp12
       host: orion.isp12.local
       port: 17774
       username: DOMAIN\svc_swis_ro
       password_env: SWIS_ISP12_PASSWORD
       verify_tls: false            # or ca_bundle: /app/certs/orion-ca.pem (mount it)
       network_id: isp12            # part of every stable ID
   ```

3. **Pass the secrets as environment variables** on the `collector` service: `SWIS_ISP12_PASSWORD`, `SWCOLLECT_HOOK_TOKEN` and `SWCOLLECT_PG_PASSWORD`.
4. **Change the service command** to `serve --network isp12` (repeat `--network` per network), or leave it out to collect every read-only profile.
5. **Let the collector reach Orion.** The base compose network is internal: it has no route to Orion either. Attach the collector to a network that reaches Orion, in an override that adds the network (like `docker-compose.hook.yml` does for the push port). It needs no internet route.
6. **Publish the push receiver** for Orion: `-f deploy/docker-compose.hook.yml` publishes `:18090`. Then set up the alert action: [orion-alert-action.md](orion-alert-action.md).

**First start.** `discover` runs at once (the network has no catalog yet). Every other job then follows its schedule.

## 4. Operating it

| Task | Command (inside the collector container: `docker compose exec collector …`) |
|---|---|
| what is due and why | `python -m swcollect schedule --network isp12` |
| run jobs now | `python -m swcollect run --network isp12 --once inventory metrics` |
| quality report | `python -m swcollect verify --network isp12` → `reports/verify-*.json` (volume `reports`) |
| data-model document | `python -m swcollect erd --network isp12` → `docs/data-model.md` / `.html` |
| a job's history | `SELECT * FROM sw_meta.sync_run ORDER BY run_id DESC` |
| what SWIS has vs what we hold | `SELECT * FROM sw_meta.coverage WHERE run_id = …` |
| what changed | `sw_meta.change_log`; per record, `sw_core.v_<table>_before_after` |
| what failed a rule | `sw_core.dead_letter` (open: `resolved_at IS NULL`), `sw_meta.raw_quarantine`, `sw_meta.loki_rejected` |
| alerts push vs poll | `sw_meta.alert_reconcile` |

**Logs:** `docker compose logs -f collector`.

**Dashboards (Grafana).** Publish Grafana for operators with `-f deploy/docker-compose.ui.yml` (port 13000), and set
`SWCOLLECT_GRAFANA_PASSWORD` (admin) and `SWCOLLECT_RO_PASSWORD` (the read-only database role) first. Grafana reads
PostgreSQL only as `swcollect_ro`, created by `deploy/init-ro.sh` when the data volume is created. For a volume made
before that script existed, run it once: `docker compose exec db sh /docker-entrypoint-initdb.d/91-swcollect-ro.sh`.
The seven dashboards (folder "swcollect") are generated by `python -m swcollect dashboards` into
`deploy/grafana/dashboards` and mounted read-only; Grafana fetches nothing from the internet (telemetry, update and
news checks, the plugin catalog and preinstalled plugins are off). `swcollect_ro` can read `sw_raw.ncm_configarchive`,
which holds full configuration text: revoke that if dashboard users must not see it.

**What reached PostgreSQL:** `python -m swcollect dbstats --network isp12` lists rows per schema and table, and every
empty collected table with its coverage status.

**Schedules, policies and exclusions** live in [catalog/collector.yaml](../catalog/collector.yaml), which the collector re-reads every cycle. Every value in it is a proposal until approved.

## 5. Backup and upgrade

- **PostgreSQL:** run `docker compose exec db pg_dump -U swcollect -Fc swcollect > swcollect.dump`. TimescaleDB needs `timescaledb_pre_restore()` / `timescaledb_post_restore()` around a restore.
- **Loki:** the `lokidata` volume (filesystem storage).
- **Upgrade:** bring the new folder through the same bundle path, then `docker compose build && docker compose up -d`. Schema changes are additive: new columns are added, and nothing is dropped.

## 6. Ports

All of these exist only on the internal network unless an override publishes them:

| Service | Port | Notes |
|---|---|---|
| collector (push receiver) | 18090 | publish with `docker-compose.hook.yml` |
| PostgreSQL | 5432 | dev override: 15432 on 127.0.0.1 |
| Loki | 3100 | dev override: 13100 on 127.0.0.1 |
| mock SWIS | 17774 | test only |
| Grafana | 3000 | `docker-compose.ui.yml`: 13000; dev override and demo: 13000 on 127.0.0.1 |
